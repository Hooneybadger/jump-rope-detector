# 뜀결 (Ttwimgyeol)

> 문서 최종 변경일: **2026-09-21**

> **동작을 읽고, 리듬을 기록하다**

MediaPipe Pose 기반 실시간 줄넘기 측정 웹 애플리케이션입니다. 기존 프로젝트의 검증된 모아뛰기·번갈아뛰기·이중뛰기 카운팅 엔진은 유지하고, 화면·인증·권한·데이터 저장·배포 구조를 새로 만들었습니다.

브라우저가 PC 웹캠을 직접 열기 때문에 Docker 컨테이너에 카메라 장치를 연결할 필요가 없습니다. 촬영 프레임은 로그인된 브라우저와 서버 사이의 WebSocket으로 전달되며 저장되지 않습니다. 서버는 MediaPipe Pose와 선택된 카운팅 엔진으로 프레임을 처리하고, 압축 영상 대신 가벼운 관절 좌표와 카운트 상태만 브라우저에 반환합니다. 카메라 원본은 브라우저에서 바로 표시되어 서버 응답 속도와 관계없이 부드럽게 보입니다.

## 주요 기능

- 모아뛰기, 번갈아뛰기, 이중뛰기 실시간 측정
- 전신 인식 후 준비 1초와 사용자가 선택한 1~30초 카운트다운을 거쳐 자동 시작
- 데스크톱·태블릿·모바일 반응형 화면과 전체 화면 측정
- DB 기반 로그인·회원가입·비밀번호 재설정, 계정 잠금, 관리자/일반 사용자 역할
- 사용자별 종목 사용 권한 및 기록 조회 권한
- 사용자별 전체 측정 이력 저장, 상세 재조회·PDF 다운로드·선택/전체 삭제
- 로그인 사용자의 이름·이메일·비밀번호 수정 및 저장과 관리자 사용자 선택 삭제
- 로그인·종목 선택 화면의 줄넘기 동작 SVG와 가독성을 고려한 반응형 글자 크기
- 사용자 생성·권한 변경·로그인·측정 시작/완료 감사 로그
- PostgreSQL 영속 저장, Alembic 스키마 마이그레이션
- Nginx, FastAPI, PostgreSQL로 구성된 Docker Compose 실행 환경

## 2026-09-21 개선 내역

### 측정 시작과 카운팅 정확도

- 이중뛰기에만 적용되던 느슨한 `signal.detected` 준비 조건을 제거했습니다. 세 종목 모두 머리·어깨·팔·몸통·무릎·발 랜드마크가 1초간 안정적으로 보인 뒤에만 카운트다운을 시작합니다.
- 카운트다운 중 전신 인식이 기준 시간 이상 끊기면 다시 자세 탐색 단계로 돌아가므로, 사용자가 프레임 밖에 있는 상태에서 측정이 시작되지 않습니다.
- 종목별 기존 상태기계와 보정 로직은 유지하면서 MediaPipe의 `smooth_landmarks`를 모아뛰기와 번갈아뛰기에도 적용하고, 입력 RGB 버퍼를 읽기 전용으로 전달해 불필요한 복사를 줄였습니다.
- 새로운 실시간 프레임워크를 추가하는 방식과 현재 구조를 비교해, 로컬 웹캠 표시와 서버 추론을 분리한 FastAPI·WebSocket 파이프라인을 유지했습니다. 한 번에 한 프레임만 전송해 지연이 누적되지 않고, 카운팅 엔진은 안정화된 관절 좌표를 받습니다.

### 프로필 편집

- 상단 프로필에서 이름과 이메일을 직접 수정하고 저장할 수 있습니다.
- 비밀번호는 선택적으로 변경할 수 있으며 현재 비밀번호를 다시 확인합니다. 변경 시 현재 세션을 제외한 다른 로그인 세션을 종료합니다.
- 중복 이메일, 잘못된 현재 비밀번호, 입력 형식 오류는 프로필 폼 안에서 바로 안내합니다.

### 브랜드와 화면 디자인

- 기존 서비스명과 슬로건을 제거하고, 프로젝트 역할을 담은 **뜀결 (Ttwimgyeol)**과 **동작을 읽고, 리듬을 기록하다**로 교체했습니다.
- 모아뛰기·번갈아뛰기·이중뛰기의 자세가 각각 드러나는 남성 전신 응원 GIF와 정지 포스터를 측정 패널에 적용했습니다.
- 카메라 안내의 발 중심 이미지를 전신 인물 아이콘으로 바꿔 머리부터 발끝까지 프레임에 맞춰야 한다는 의미를 분명히 했습니다.
- 제목은 균형 줄바꿈과 제한된 음수 자간을 사용하고, 본문·레이블·표·버튼은 타입 스케일에 맞는 행간과 기본 장평을 사용하도록 전체 타이포그래피를 점검했습니다.
- 브랜드 결정과 컴포넌트 규칙을 `brand-spec.md`와 `DESIGN.md`에 같은 기준으로 기록했습니다.

### 계정과 관리 기능

- 회원가입한 계정으로 즉시 로그인할 수 있으며, 아이디·이메일·표시 이름과 Argon2id로 해시한 비밀번호를 DB에서 관리합니다.
- **비밀번호 찾기**에서 일회용 재설정 링크를 발급합니다. 토큰은 해시하여 저장하고 30분 후 만료되며 한 번만 사용할 수 있습니다.
- 로그인 후 **프로필**에서 아이디, 역할과 사용 가능한 측정 모드를 확인하고 이름·이메일·비밀번호를 수정할 수 있습니다.
- 측정 기록 표에 개별 선택과 전체 선택을 추가했습니다. 선택한 기록을 한 번에 삭제할 수 있으며, 진행 중인 측정은 선택 및 삭제할 수 없습니다.
- 관리자 사용자 표에서도 개별 선택·전체 선택·일괄 삭제를 지원합니다. 현재 로그인한 관리자 본인 계정은 선택 및 삭제할 수 없습니다.
- 일반 사용자는 자신의 기록만 관리할 수 있고, 관리자는 권한 범위 안에서 전체 사용자의 기록을 관리할 수 있습니다.

### 실시간 측정 성능

- WebSocket 자체가 아니라 `프레임 업로드 → 자세 추론 → 서버 JPEG 재인코딩 → 브라우저 디코딩`을 직렬로 기다리던 흐름을 주된 지연 원인으로 확인했습니다.
- WebRTC로 교체하지 않고 카메라 미리보기와 AI 분석 전송을 분리했습니다. 따라서 로컬 카메라 영상은 추론이나 네트워크 왕복을 기다리지 않고 표시됩니다.
- 분석 입력은 512×288, 최대 12fps, JPEG 품질 62%로 제한하며 요청은 한 번에 하나만 전송합니다.
- 서버는 처리 영상을 다시 인코딩하지 않고 관절 좌표, 카운트 상태와 처리 시간만 반환합니다. 브라우저가 원본 영상 위에 자세 오버레이를 직접 그립니다.
- 측정 화면에서 서버 처리 시간과 네트워크 왕복 시간을 확인할 수 있어 배포 장비별 성능을 비교할 수 있습니다.

## 실행 요구사항

- Docker Desktop 또는 Docker Engine + Docker Compose v2
- 웹캠이 연결된 PC
- Chrome, Edge 등 `getUserMedia`와 WebSocket을 지원하는 최신 브라우저

로컬의 `http://localhost`는 브라우저가 카메라 사용을 허용하는 보안 컨텍스트로 취급합니다. 다른 PC나 도메인에서 접속할 때는 반드시 HTTPS를 적용해야 합니다.

## 빠른 실행

git bash에서 프로젝트 디렉터리로 이동합니다.

```bash
cd jump-rope-detector
cp .env.example .env
```

`.env`를 열어 아래 두 값을 반드시 변경합니다.

```dotenv
POSTGRES_PASSWORD=충분히_긴_무작위_DB_비밀번호
ADMIN_PASSWORD=12자_이상의_관리자_비밀번호
```

비밀번호는 코드나 Git에 커밋하지 마세요. DB 접속 문자열을 직접 조합하지 않고 개별 환경 변수로 전달하므로 `@`, `:`, `/` 같은 특수문자도 사용할 수 있습니다.

서비스를 빌드하고 시작합니다.

```powershell
docker compose up --build -d
docker compose ps
```

브라우저에서 [http://localhost:8080](http://localhost:8080)을 열고 `.env`의 `ADMIN_USERNAME`과 `ADMIN_PASSWORD`로 로그인합니다. 최초 실행 시 DB 마이그레이션과 관리자 계정 생성이 자동 수행됩니다.

로그 확인과 종료 방법은 다음과 같습니다.

```powershell
docker compose logs -f app
docker compose down
```

`docker compose down`은 DB 볼륨을 보존합니다. 아래 명령은 모든 사용자와 측정 기록을 포함한 DB 볼륨을 삭제하므로 초기화가 정말 필요한 경우에만 사용하세요.

```powershell
docker compose down -v
```

## 최초 설정

사용자는 첫 화면에서 직접 회원가입할 수 있습니다. 가입한 아이디·이메일·암호화된 비밀번호는 모두 DB에서 관리되며, 로그인 화면의 **비밀번호 찾기**도 같은 계정 정보와 연결됩니다. SMTP를 설정하면 이메일로 재설정 링크를 보내고, 개발 환경에서는 화면에서 바로 재설정 흐름을 확인할 수 있습니다.

관리자는 로그인 후 상단의 **관리** 메뉴에서도 사용자를 추가할 수 있습니다.

1. **사용자 추가**를 누릅니다.
2. 아이디, 표시 이름, 12자 이상의 임시 비밀번호를 입력합니다.
3. 모아뛰기, 번갈아뛰기, 이중뛰기, 기록 조회 권한을 선택합니다.
4. 생성 후 사용자 목록의 체크박스로 종목 권한을 즉시 변경할 수 있습니다.

관리자는 모든 종목과 전체 사용자의 측정 기록을 볼 수 있습니다. 일반 사용자는 자신에게 부여된 종목만 시작할 수 있고, 기록 조회 권한이 있을 때 자신의 전체 기록을 확인합니다.

### 프로필 수정과 선택 삭제

- 상단의 **프로필**을 누르면 이름과 이메일을 바로 수정할 수 있습니다. 비밀번호를 바꾸려면 **비밀번호 변경**을 펼치고 현재 비밀번호와 새 비밀번호를 입력합니다.
- 기록 화면에서 삭제할 행을 선택하거나 머리글 체크박스로 삭제 가능한 기록을 모두 선택한 다음 **선택 삭제**를 누릅니다.
- 관리자 화면에서도 같은 방식으로 여러 사용자를 삭제할 수 있습니다. 본인 계정의 체크박스는 비활성화됩니다.
- 선택 삭제는 확인 대화상자를 한 번 더 거치며, 서버에서도 CSRF·소유권·관리자 권한을 다시 검증합니다.

## 측정 워크플로우

1. 로그인 후 훈련 화면에서 사용할 줄넘기 종목을 선택합니다.
2. 브라우저의 카메라 사용 요청을 허용합니다.
3. 카메라에서 머리부터 발끝까지 보이도록 약 2~3m 거리를 확보합니다.
4. 서버가 머리, 팔, 몸통, 다리와 발을 1초간 안정적으로 인식하면 사용자가 정한 카운트다운이 시작됩니다.
5. 선택한 카운팅 엔진이 프레임을 분석하고 횟수와 측정 시간을 실시간으로 갱신합니다.
6. 목표 시간이 끝나거나 **측정 끝내기**를 누르면 결과가 PostgreSQL에 자동 저장됩니다.
7. 완료 화면에서 이번 결과를 PDF로 바로 내려받거나 **전체 기록 보기**로 이동할 수 있습니다.
8. 전체 기록 표에서 이전 결과를 상세 조회·PDF 다운로드하거나 여러 기록을 선택해 한 번에 삭제할 수 있습니다.

세 종목은 다음 원본 알고리즘을 그대로 사용합니다.

| 종목       | 엔진                                   | 주요 판정 신호                             |
| ---------- | -------------------------------------- | ------------------------------------------ |
| 모아뛰기   | `basic_jump/counter_engine.py`       | 양발 접지, 골반 반동, 좌우 대칭            |
| 번갈아뛰기 | `alternating_jump/counter_engine.py` | 좌우 지지 발 전환, 발·무릎·손목 특징     |
| 이중뛰기   | `double_jump/counter_engine.py`      | 체공 주기, 골반·발 움직임, 손목 회전 분류 |

## 시스템 구조

```text
웹캠
  ↓ 브라우저 getUserMedia
반응형 웹 UI
  ↓ 인증 쿠키 + Origin 검증 WebSocket (저해상도 JPEG 업로드)
Nginx :8080
  ↓
FastAPI :8000
  ├─ MediaPipe Pose
  ├─ 줄넘기 카운팅 엔진 3종
  ├─ 인증·회원가입·비밀번호 재설정
  ├─ RBAC·CSRF·감사 로그
  ├─ 측정 기록 조회·삭제·PDF 생성
  └─ Alembic 마이그레이션
       ↓
PostgreSQL 17 영속 볼륨
```

분석 결과는 관절 좌표·카운트·상태·처리 시간만 JSON으로 내려옵니다. 기존에는 서버가 분석한 매 프레임을 다시 JPEG로 인코딩하고 브라우저가 디코딩한 뒤에 다음 프레임을 보내, 추론 시간과 영상 왕복 시간이 카메라 화면의 프레임률을 직접 제한했습니다. WebSocket은 이 구조의 운반 수단일 뿐 병목의 원인은 아니므로, 별도 시그널링·ICE·미디어 서버가 필요한 WebRTC로 교체하는 대신 영상 표시와 분석 전송을 분리했습니다. 분석 전송은 512×288, 최대 12fps, JPEG 품질 62%로 제한하고 서버 응답을 받은 뒤 다음 프레임을 보내 과부하를 방지합니다.

- `web`: 외부 요청과 WebSocket을 받는 Nginx 리버스 프록시
- `app`: FastAPI API, 정적 UI, MediaPipe 처리, 카운팅 엔진
- `db`: 사용자, 비밀번호 재설정 토큰, 서버 세션, 운동 기록, 감사 로그를 저장하는 PostgreSQL

Streamlit과 `streamlit-webrtc`는 제거했습니다. UI 크기와 상태 관리, 인증/RBAC, DB 트랜잭션을 일관되게 제어하기 위해 브라우저 UI + FastAPI 구조로 교체했습니다. 카메라는 여전히 사용자의 브라우저에서만 열리며, 서버에는 영상 파일을 저장하지 않습니다.

| `POSTGRES_USER`          | PostgreSQL 사용자                          |
| `POSTGRES_PASSWORD`      | PostgreSQL 비밀번호                        |
| `ADMIN_USERNAME`         | 최초 관리자 아이디                         |
| `ADMIN_PASSWORD`         | 최초 관리자 비밀번호, 최소 12자            |
| `ADMIN_DISPLAY_NAME`     | 관리자 표시 이름                           |
| `COOKIE_SECURE`          | HTTPS 운영 환경에서는`true`              |
| `ALLOWED_HOSTS`          | 허용할 Host 헤더 목록                      |
| `ALLOWED_ORIGINS`        | WebSocket 연결을 허용할 정확한 Origin 목록 |
| `MAX_CONCURRENT_STREAMS` | 동시에 실행할 실시간 측정 수, 기본 4       |
| `PUBLIC_BASE_URL`        | 비밀번호 재설정 링크에 사용할 서비스 주소  |
| `SMTP_HOST`              | 비밀번호 재설정 이메일을 보낼 SMTP 호스트  |
| `SMTP_PORT`              | SMTP 포트, 기본 587                        |
| `SMTP_USERNAME`          | SMTP 인증 사용자                           |
| `SMTP_PASSWORD`          | SMTP 인증 비밀번호                         |
| `SMTP_FROM`              | 비밀번호 재설정 메일 발신 주소             |
| `SMTP_STARTTLS`          | SMTP STARTTLS 사용 여부, 기본`true`      |

LAN이나 도메인으로 서비스할 경우 실제 호스트와 Origin을 모두 설정합니다.

```dotenv
COOKIE_SECURE=true
ALLOWED_HOSTS=jump.example.com
ALLOWED_ORIGINS=https://jump.example.com
```

현재 Nginx 설정은 로컬 HTTP용입니다. 운영 환경에서는 앞단 리버스 프록시 또는 로드 밸런서에서 TLS 인증서를 적용하고 WebSocket 업그레이드 헤더를 전달하세요.

## 보안 설계

- 비밀번호는 Argon2id로 해시하며 평문으로 저장하지 않습니다.
- 세션 쿠키는 `HttpOnly`, `SameSite=Strict`로 발급하고 운영 HTTPS에서는 `Secure`를 사용합니다.
- DB에는 세션 토큰 원문 대신 SHA-256 해시만 저장합니다.
- 상태 변경 API는 CSRF 토큰을 검증합니다.
- 운동 기록 상세 조회·PDF·삭제는 사용자 소유권과 기록 조회 권한을 검증합니다.
- 비밀번호 재설정 토큰은 SHA-256 해시로 저장하며 30분 후 만료되고 한 번만 사용할 수 있습니다.
- WebSocket은 로그인 세션, Origin, 사용자별 종목 권한을 연결 시점에 검증합니다.
- 로그인은 IP 단위 요청 제한과 계정 단위 5회 실패/15분 잠금을 적용합니다.
- CSP, 클릭재킹 방지, MIME 스니핑 방지, 카메라 권한 제한 헤더를 적용합니다.
- 이미지 크기와 해상도, 동시 스트림 수를 제한합니다.
- 앱 컨테이너는 비루트 사용자, 읽기 전용 파일시스템, Linux capability 제거, `no-new-privileges`로 실행합니다.
- PostgreSQL 포트는 호스트에 공개하지 않습니다.
- 관리자 본인의 계정을 비활성화하거나 일반 사용자로 낮추는 변경을 차단합니다.
- 런타임 이미지에서 패키지 설치 도구(`pip`, `setuptools`)를 제거해 공격 표면을 줄입니다.

운영에서는 `.env`를 비밀 저장소로 대체하고, DB 백업·TLS·로그 보존 정책을 별도로 구성하세요.

기존 카운팅 엔진이 사용하는 legacy `mp.solutions.pose` API는 MediaPipe 0.10.21과 protobuf 4.x 조합을 요구합니다. 현재 알려진 protobuf 취약점의 영향면을 줄이기 위해 애플리케이션은 protobuf 파일·메시지를 외부 입력으로 받지 않고, 크기 제한된 JPEG 프레임만 디코딩합니다. 향후 MediaPipe Tasks Pose Landmarker로 추출 계층을 이전하면 protobuf 6 이상으로 갱신할 수 있습니다.

## 개발 및 검증

로컬 Python 개발은 3.11을 권장합니다. MediaPipe 0.10.21의 플랫폼별 wheel 지원 범위 때문에 다른 Python 버전에서는 설치되지 않을 수 있습니다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
pytest -q
ruff check app tests
node --check static/app.js
```

Docker 구성 검증과 이미지 빌드는 다음 명령으로 수행합니다.

```powershell
docker compose config --quiet
docker compose build app
```

현재 자동화 테스트는 회원가입, 프로필·비밀번호 수정, 중복 이메일 차단, 비밀번호 재설정, 기록 전체 조회, 상세 조회, PDF 생성, 개별·일괄 삭제, 관리자 사용자 일괄 삭제, 사용자 간 기록 접근 차단, 이중뛰기 전신 준비 게이트를 포함합니다. 2026-09-21 기준 전체 테스트 24개를 통과했으며 Ruff와 JavaScript 문법 검사도 완료했습니다.

> 실제 프레임률과 지연시간은 카메라, CPU/GPU, 네트워크 환경에 따라 달라집니다. 배포 대상 장비에서는 측정 화면의 **처리 시간**과 **왕복 시간**을 확인해 성능을 최종 점검하세요.

## 문제 해결

### 카메라 요청이 나타나지 않음

- 주소가 `http://localhost:8080`인지 확인합니다.
- 브라우저 주소창의 사이트 권한에서 카메라를 허용합니다.
- 다른 앱이 웹캠을 점유하고 있지 않은지 확인합니다.
- 원격 접속이면 HTTP가 아니라 HTTPS를 사용합니다.

### 계속 “자세 찾는 중”으로 표시됨

- 머리부터 발끝까지 화면 안에 들어오도록 뒤로 이동합니다.
- 발과 바닥이 잘 구분되도록 조명을 밝게 합니다.
- 카메라를 허리보다 낮게 두지 말고 전신 정면을 촬영합니다.

### 로그인이 되지 않음

- `.env`의 관리자 아이디와 비밀번호를 확인합니다.
- 5회 실패했다면 15분 후 다시 시도합니다.
- 이미 생성된 DB 볼륨에서는 `.env`의 관리자 비밀번호 변경이 기존 계정 비밀번호를 덮어쓰지 않습니다.

### 비밀번호 재설정 메일이 오지 않음

- `.env`의 `SMTP_HOST`, `SMTP_FROM`과 SMTP 인증 정보를 확인합니다.
- `PUBLIC_BASE_URL`이 사용자가 실제로 접속할 수 있는 서비스 주소인지 확인합니다.
- 개발 환경에서는 메일 대신 화면에 이어지는 재설정 흐름으로 기능을 확인할 수 있습니다.

### PDF 다운로드 또는 기록 삭제가 되지 않음

- 일반 사용자는 자신의 기록만 관리할 수 있습니다.
- 일반 사용자 계정에 기록 조회 권한이 부여되어 있는지 관리자에게 확인합니다.
- 아직 측정 중인 기록은 삭제할 수 없습니다.

### 컨테이너 상태가 healthy가 아님

```powershell
docker compose ps
docker compose logs app
docker compose logs db
```

DB 비밀번호나 마이그레이션 오류를 확인한 뒤 서비스를 다시 시작합니다.

로그에 `password authentication failed`가 표시되면 기존 DB 볼륨을 만든 뒤 `.env`의 `POSTGRES_PASSWORD`를 변경한 경우일 수 있습니다. PostgreSQL 컨테이너의 환경 변수만 바꿔도 기존 DB 역할의 비밀번호는 자동으로 바뀌지 않습니다. 데이터를 보존하려면 다음 명령으로 DB 콘솔에 접속한 뒤 현재 `.env`의 비밀번호를 두 번 입력합니다. 사용자명이나 DB 이름을 변경했다면 명령의 `jump_rope`도 같은 값으로 바꾸세요.

```powershell
docker compose exec db psql -U jump_rope -d jump_rope
\password jump_rope
\q
docker compose up -d --wait
```

로그에 `invalid interpolation syntax`와 `%21` 같은 URL 인코딩 값이 표시되는 문제는 Alembic 설정에서 특수문자 비밀번호를 처리하도록 수정했습니다. 최신 이미지를 다시 빌드하세요.

```powershell
docker compose up --build -d --wait
```

저장된 데이터가 필요 없는 개발 환경에서만 `docker compose down -v`로 DB 볼륨을 초기화할 수 있습니다. 이 명령은 사용자와 측정 기록을 모두 영구 삭제합니다.
